# Нурсат — первый этап, отчёт к 14 сентября

Подготовлено 10 сентября 2026 года. Ветка: `codex/nursat-backend-foundation`.

## Цель этапа

Подготовить общий backend-фундамент, чтобы Айжан могла строить бизнес-логику,
а Анвар, Абылай и Мират — согласовать интерфейсы своих приложений.

## Реализация

- Создан Django-проект в `backend/` с DRF и PostgreSQL-настройками.
- Подготовлены Dockerfile, Compose (`web` + `db`) и `.env.example`.
- Добавлены User с email-логином, email_verified_at и хешированием паролей,
  а также OrganizerProfile с контактами и ссылкой на симуляцию payout.
- Создана первая миграция с case-insensitive уникальностью email в БД.
- Модели доступны во внутренней Django admin.
- Добавлен публичный `/api/health` с проверкой PostgreSQL и ответом 503
  при недоступности базы без раскрытия внутренних ошибок.
- Подготовлен workflow GitHub Actions: Compose, миграции, тесты и Ruff.

## Проверки

Проверено 10 сентября на Docker Desktop с PostgreSQL 16.15:

- `docker compose config --quiet` — корректная конфигурация.
- `docker compose up --build -d --wait --wait-timeout 120` — образ собран,
  оба контейнера healthy, миграции применены на новой базе.
- `python manage.py check` — замечаний нет.
- `python manage.py makemigrations --check --dry-run` — расхождений моделей
  и миграций нет.
- `python manage.py test --noinput` внутри контейнера — **13 тестов прошли
  на PostgreSQL**, тестовая база удалена после выполнения.
- `ruff check .` и `ruff format --check .` внутри контейнера — успешно.
- Запрос с компьютера к `/api/health` — HTTP 200 и
  `{"status":"ok","database":"ok"}`; `/admin/login/` — HTTP 200.

Тесты проверяют email-нормализацию и вход, хеширование паролей, запрет
входа при блокировке, отсутствие привилегий по умолчанию, ограничения
создания суперпользователя, уникальность email/профиля на уровне БД,
пользовательские admin forms и health-check при доступной/недоступной БД.
Недоступность БД в негативном тесте имитируется исключением драйвера;
штатные тесты и миграции выполняются на настоящем PostgreSQL.

GitHub Actions настроен, а его команды проверены локально в Docker;
удалённый запуск требует push/PR. Актуальный origin/main проверен через
fetch: новых коммитов относительно исходной базы ветки нет.

## Демонстрация на отчёте

1. Показать запуск `docker compose up --build -d --wait`.
2. Открыть `/api/health` и объяснить проверку соединения с БД.
3. Создать локального суперпользователя через `createsuperuser` и показать
   User/OrganizerProfile во внутренней админке.
4. Показать auth API draft и проект модели данных.
5. Запустить `docker compose exec web python manage.py test`.
